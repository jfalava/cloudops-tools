# Persistent TOTP secret on WSL

This setup keeps your credential tooling and TOTP state on Windows while still letting you run commands from WSL.
Instead of installing tools inside WSL, install and initialize them on Windows, then point WSL aliases to the Windows `.exe` binaries.
This is useful when WSL does not reliably persist credentials after shutdown/restart.

## When to Use This

Use this approach when:

- Credentials or TOTP state in WSL do not persist after shutdown/restart.
- You want one persistent credential/TOTP setup shared between Windows and WSL shells.

## 1) Install Tools on Windows

Install the required tools in Windows:

```powershell
npm install -g @cloudops-tools/cli
```

Confirm binaries are available on Windows:

```powershell
Get-Command cloudops-tools.exe
```

## 2) Run TOTP Setup on Windows

Run your TOTP setup command from Windows so secrets/state live on the Windows side:

```powershell
cloudops-tools setup-totp
```

## 3) Add WSL Aliases to Windows Binaries

Add aliases in your shell profile (`~/.zshrc` or `~/.bashrc`) so WSL calls the Windows executables:

```bash
alias cloudops-tools='/mnt/path/to/the/binary/cloudops-tools.exe'
```

## 4) Reload Profile and Verify in WSL

```bash
source ~/.zshrc
type cloudops-tools
cloudops-tools version
```

Use `source ~/.bashrc` if you configured Bash instead of Zsh.

## Troubleshooting

- Validate path conversion with `wslpath`:

```bash
wslpath 'path\to\binary\cloudops-tools.exe'
```

- If an alias is not available, ensure it is in the correct profile file and that your shell session reloaded it.
- If command names differ after installation, inspect the Windows bin directory and alias the exact executable name.
