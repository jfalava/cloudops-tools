# Troubleshooting

## Missing AWS Credentials

Symptom:

- Errors similar to credential provider failures.

Checks:

```bash
aws sts get-caller-identity
```

If this fails, configure credentials first:

```bash
export AWS_ACCESS_KEY_ID=...
export AWS_SECRET_ACCESS_KEY=...
export AWS_REGION=us-east-1
```

You can also use shared credentials in `~/.aws/credentials`.

## Access Denied / Unauthorized

Symptom:

- `AccessDenied` errors for specific services or actions.

Actions:

- Confirm the active identity can call read APIs for the targeted services.
- Reduce scope to isolate failing services:

```bash
cloudops-tools init --services EC2 --region us-east-1 --debug
```

## Region Errors

Symptom:

- Invalid region names or service/region mismatch behavior.

Actions:

- Validate region list formatting (comma-separated, no spaces in names).
- Start with one known-good region:

```bash
cloudops-tools --region us-east-1
```

## Long or Noisy Runs

Actions:

- Limit services and regions for targeted debugging:

```bash
cloudops-tools init --services EC2,RDS --limit-regions us-east-1
```

- Use `--skip-global` to reduce global-service scan time.
- Use `--only-global` when you only need global services.

## LetMe / --use-letme

Symptom:

- `letme` preflight check fails or times out.
- `Unable to read stored TOTP secret` appears.
- `Missing required --account <profile> with --use-letme` appears.

Actions:

1. Confirm `letme` is installed and on your `PATH`:

```bash
letme --version
```

2. If TOTP is not configured yet, set it up before using `--use-letme`:

```bash
cloudops-tools setup-totp
```

3. Re-run your scan with both `--use-letme` and `--account`:

```bash
cloudops-tools --use-letme --account engineering-prod --region us-east-1
```

Notes:

- `--use-letme` requires `--account <profile>` so the CLI knows which profile to activate.
- If `letme` is missing, install it and restart your shell so `PATH` is updated.

## Help and Diagnostics Flags

```bash
cloudops-tools --help
cloudops-tools --help-examples
cloudops-tools --version
```

Use `--debug` on scan or describe commands for full stack traces:

```bash
cloudops-tools describe ec2 us-east-1 i-1234567890abcdef0 --debug
```
