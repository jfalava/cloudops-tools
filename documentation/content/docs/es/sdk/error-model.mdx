# Modelo de Errores

Las operaciones y servicios del SDK están modeladas como valores `Effect`, por lo que los errores son valores que puedes clasificar, inspeccionar y manejar de forma estructurada.

## Tipos de error exportados

| Tipo de error     | Origen típico                                | Notas                                                                          |
| ----------------- | -------------------------------------------- | ------------------------------------------------------------------------------ |
| `AwsError`        | Respuestas del AWS SDK / servicios           | Incluye `service`, `region`, `code`, `statusCode` y helpers como `isRetryable` |
| `CredentialError` | Fallos al cargar credenciales / auth         | Suele resolverse corrigiendo entorno o perfil de autenticación                 |
| `ValidationError` | Entradas u opciones inválidas                | El llamador debe corregir los datos antes de reintentar                        |
| `FileSystemError` | Operaciones de lectura/escritura de archivos | Muy común en flujos de generación de reportes / salida                         |

## Escenarios de fallo frecuentes

| Escenario                             | Señal típica                                     | Recomendación de manejo                                 |
| ------------------------------------- | ------------------------------------------------ | ------------------------------------------------------- |
| Throttling o fallo transitorio en AWS | `AwsError` con código/status retryable           | Reintentar con backoff exponencial y límite de intentos |
| Credenciales inválidas o expiradas    | `CredentialError` o `AwsError.isCredentialError` | Refrescar sesión/perfil y reintentar                    |
| Región, servicio o filtro inválido    | `ValidationError`                                | Fallar rápido y mostrar mensaje accionable al usuario   |
| Fallo al escribir archivo de salida   | `FileSystemError`                                | Registrar ruta destino y abortar la fase de salida      |

## Patrón de reintento para errores AWS

```ts
import { Duration, Effect, Schedule } from "effect";
import { AwsError, ComputeService, SdkLive } from "@cloudops-tools/sdk";

const program = Effect.gen(function* (_) {
  const compute = yield* _(ComputeService);
  return yield* _(compute.describeEC2("us-east-1"));
}).pipe(
  Effect.retry(
    Schedule.exponential(Duration.millis(250)).pipe(
      Schedule.intersect(Schedule.recurs(4)),
      Schedule.whileInput((error) => error instanceof AwsError && error.isRetryable),
    ),
  ),
);

await Effect.runPromise(program.pipe(Effect.provide(SdkLive)));
```

Este patrón:

- Usa backoff exponencial empezando en 250 ms
- Limita a 4 reintentos adicionales (5 intentos totales)
- Solo reintenta si el error es marcado como `retryable`

## Manejo específico por tag de error

```ts
import { Effect } from "effect";
import { CredentialError, UtilService, SdkLive } from "@cloudops-tools/sdk";

const accountIdProgram = Effect.gen(function* (_) {
  const util = yield* _(UtilService);
  return yield* _(util.getAccountId());
}).pipe(
  Effect.catchTag("CredentialError", (error: CredentialError) =>
    Effect.fail(new Error(`Problema de credenciales: ${error.message}`)),
  ),
);

await Effect.runPromise(accountIdProgram.pipe(Effect.provide(SdkLive)));
```

### Ventajas del enfoque con `catchTag`

- Tipado seguro: TypeScript sabe exactamente qué tipo de error estás manejando
- Evita chequeos manuales con `instanceof` en muchos casos
- Permite propagar o transformar errores de forma declarativa

## Resumen rápido de recomendaciones

- **Transient / throttling** → `Effect.retry` + `Schedule` con `isRetryable`
- **Credenciales** → `catchTag("CredentialError")` → refrescar sesión
- **Validación** → fallar rápido con mensaje claro al usuario
- **Sistema de archivos** → capturar `FileSystemError` y loguear ruta + contexto

Con este modelo de errores estructurado puedes crear flujos robustos, predecibles y fáciles de depurar en tus integraciones con el SDK de CloudOps.
