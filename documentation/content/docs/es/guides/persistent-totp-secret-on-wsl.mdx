# Secreto TOTP persistente en WSL

Esta configuración mantiene tus herramientas de credenciales y el estado TOTP en Windows, pero te permite ejecutar comandos desde WSL.
En vez de instalar las herramientas dentro de WSL, instálalas e inicialízalas en Windows y después apunta alias de WSL a los binarios `.exe` de Windows.
Esto es útil cuando WSL no conserva de forma confiable las credenciales después de apagar o reiniciar.

## Cuándo usar esta guía

Usa este enfoque cuando:

- Las credenciales o el estado TOTP en WSL no persisten tras apagar/reiniciar.
- Quieres una configuración persistente de credenciales/TOTP compartida entre Windows y shells de WSL.

## 1) Instalar herramientas en Windows

Instala las herramientas necesarias en Windows:

```powershell
npm install -g @cloudops-tools/cli
```

Confirma que el binario está disponible en Windows:

```powershell
Get-Command cloudops-tools.exe
```

## 2) Ejecutar la configuración TOTP en Windows

Ejecuta el comando de configuración TOTP desde Windows para que los secretos/estado queden del lado de Windows:

```powershell
cloudops-tools setup-totp
```

## 3) Añadir alias en WSL hacia binarios de Windows

Añade alias en tu perfil de shell (`~/.zshrc` o `~/.bashrc`) para que WSL invoque los ejecutables de Windows:

```bash
alias cloudops-tools='/mnt/path/to/the/binary/cloudops-tools.exe'
```

## 4) Recargar el perfil y verificar en WSL

```bash
source ~/.zshrc
type cloudops-tools
cloudops-tools version
```

Usa `source ~/.bashrc` si configuraste Bash en lugar de Zsh.

## Solución de problemas

- Valida la conversión de rutas con `wslpath`:

```bash
wslpath 'path\to\binary\cloudops-tools.exe'
```

- Si un alias no aparece, asegúrate de haberlo escrito en el archivo de perfil correcto y de recargar la sesión.
- Si el nombre del comando difiere tras instalar, inspecciona el directorio binario de Windows y crea el alias con el nombre exacto del ejecutable.
