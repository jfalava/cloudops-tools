# Instalación

## Requisitos previos

- **Node.js 18 o superior** y un gestor de paquetes (`npm`, `pnpm`, `Yarn` moderno/Corepack o `Bun`)
- Credenciales AWS configuradas en tu máquina. Las formas más comunes son:
  - Archivo `~/.aws/credentials`
  - Variables de entorno (`AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, etc.)

## Instalación recomendada

<Tabs items={["npm", "pnpm", "Yarn", "Bun"]}>
  <Tab value="npm">

```bash
npm install -g @cloudops-tools/cli
```

  </Tab>
  <Tab value="pnpm">

```bash

```

  </Tab>
  <Tab value="Yarn">

puntuales:


Si necesitas una instalación global, es mejor usar `npm` o `pnpm`.

Alternativa para Yarn Classic (`1.x`):

```bash
yarn global add @cloudops-tools/cli
```

## Verificar que todo se instaló correctamente

```bash
cloudops-tools --version
```

Si ves la versión (por ejemplo `0.5.x` o la que tengas instalada), ¡todo listo!
Si ejecutas simplemente `cloudops-tools` sin argumentos, verás la ayuda completa.

## ¿Cómo funciona la instalación por dentro?

El paquete `@cloudops-tools/cli` instala un pequeño lanzador.
El binario nativo real viene en dependencias opcionales específicas por plataforma:

- `@cloudops-tools/cli-darwin-arm64` → macOS Apple Silicon
- `@cloudops-tools/cli-linux-x64` → Linux x64
- `@cloudops-tools/cli-win32-x64` → Windows x64

Lo hacemos así para no enviar todos los binarios de todas las plataformas en un único paquete npm.
Esto reduce el tamaño de la instalación normal, pero algunos ejecutores temporales (`bunx`,
`pnpm dlx`) pueden requerir indicar explícitamente el paquete de plataforma.

**Plataformas con binarios precompilados disponibles actualmente:**

- Linux x64
- Windows x64
- macOS arm64 (M1/M2/M3/M4)

Si estás en otra arquitectura o sistema operativo no soportado (por ejemplo Linux arm64, Windows arm64, etc.), puedes compilar desde el código fuente:

→ [Construir el binario del CLI desde el código fuente](/es/docs/cli/build-cli)

## Configuración de credenciales AWS

CloudOps Tools usa el mecanismo estándar de resolución de credenciales de AWS SDK, en este orden de prioridad:

1. Variables de entorno
2. Archivo compartido de credenciales (`~/.aws/credentials`)
3. Roles IAM (en EC2, ECS, Lambda, etc.)

### Ejemplo rápido con variables de entorno

```bash
export AWS_ACCESS_KEY_ID=AKIAXXXXXXXXXXXXXXXX
export AWS_SECRET_ACCESS_KEY=tu-clave-secreta-muy-larga-aquí
export AWS_REGION=us-east-1        # opcional, pero muy recomendado
```

O si ya tienes configurado el archivo `~/.aws/credentials` con perfiles:

```ini
[default]
aws_access_key_id = AKIA...
aws_secret_access_key = ...

[produccion]
aws_access_key_id = AKIA...
aws_secret_access_key = ...
```

Luego puedes usar un perfil específico con el parámetro `--account`:

```bash
cloudops-tools --account produccion --region eu-west-1
```
