# uso-déjame

Utilice `--use-letme` para obtener credenciales temporales de AWS a través de `letme` antes de ejecutar los comandos de escaneo.

## Requisitos previos

Antes de usar `--use-letme`, primero debe configurar un secreto TOTP. El indicador `--use-letme` requiere autenticación TOTP para generar automáticamente códigos MFA al asumir roles a través de `letme`.

### Configurar TOTP

Configure su secreto TOTP usando el comando de configuración interactiva:

```bash
cloudops-tools setup-totp
```

Este comando:

1. Acepte su clave secreta TOTP (el secreto codificado en base32 de la configuración de su dispositivo MFA)
2. Guárdelo de forma segura utilizando un almacenamiento secreto respaldado por el sistema operativo.
3. Validar la configuración generando un token de prueba.

El secreto TOTP se almacena localmente a través de secretos Bun utilizando un almacenamiento seguro específico de la plataforma:

- **macOS**: [Llavero](https://support.apple.com/guide/keychain-access/what-is-keychain-access-kyca1083/mac)
- **Windows**: [Administrador de credenciales](https://support.microsoft.com/en-us/windows/credential-manager-in-windows-1b5c916a-6a16-889f-8581-fc16e8165ac0)
- **Linux**: [libsecret](https://github.com/GNOME/libsecret)

**Nota para usuarios de WSL**: Es posible que los entornos WSL no conserven secretos durante los reinicios debido a limitaciones en los mecanismos de almacenamiento de secretos.

## Uso

```bash
cloudops-tools --use-letme --account <profile-name> [options]
cloudops-tools init --use-letme --account <profile-name> [options]
```

## Cómo funciona

Cuando `--use-letme` está habilitado, Herramientas de CloudOps:1. Requiere que `--account <profile-name>` especifique qué perfil letme usar 2. Carga el secreto TOTP almacenado por `setup-totp` 3. Genera un código OTP basado en el tiempo 4. Ejecuta `letme obtain <profile-name>` y canaliza la OTP automáticamente 5. Establece `AWS_PROFILE=<profile-name>` para el proceso actual 6. Continúa la ejecución normal del comando utilizando las credenciales del rol asumido.

## Requisitos

- `letme` documentos oficiales: [getletme.com](https://getletme.com/)
- `letme` código fuente: [github.com/lockedinspace/letme](https://github.com/lockedinspace/letme)
- `letme` debe estar instalado y disponible en tu `PATH`
- Debes ejecutar `setup-totp` al menos una vez antes de usar `--use-letme`

## Ejemplos

### Configurar TOTP (configuración única)

```bash
cloudops-tools setup-totp
# Enter your TOTP secret when prompted
```

### Escaneo de raíz con letme

```bash
cloudops-tools --use-letme --account engineering-prod --region us-east-1
```

### iniciar escaneo con letme

```bash
cloudops-tools init --use-letme --account engineering-prod --mode security --export-format xlsx
```

### Flujo de ejemplo completo

```bash
# 1. Configure TOTP once
cloudops-tools setup-totp

# 2. Use letme with your MFA profile for any scan
cloudops-tools --region eu-south-2 --account account-in-letme-dynamodb --use-letme
```

## Casos de error

- **Falta `--account` con `--use-letme`**:
  `Missing required --account <profile> with --use-letme`

- **`letme` no instalado**:
  `letme binary not found in PATH. Install letme and try again.`

- **Secreto TOTP no configurado**:
  Ejecute `setup-totp` primero antes de usar `--use-letme`

- **Error al recuperar el secreto TOTP**:
  `Unable to read stored TOTP secret: ...`

## Consideraciones de seguridad- El secreto TOTP nunca se almacena en `config.json` ni en ningún archivo de texto sin formato.

- Los secretos son administrados por el almacén de credenciales seguro del sistema operativo.
- Considere la posibilidad de utilizar AWS IAM Identity Center (SSO) para entornos de equipo como alternativa a las configuraciones TOTP individuales.
