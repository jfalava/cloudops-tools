# init

Generate a comprehensive cross-region AWS inventory scan with advanced configuration options.

## Usage

```bash
cloudops-tools init [options]
```

## Description

The `init` command performs a full inventory scan across multiple AWS regions. Unlike the basic scan, it supports different scanning modes optimized for various use cases like security auditing or cost analysis.

## Options

| Option            | Alias | Description                                          | Default       |
| ----------------- | ----- | ---------------------------------------------------- | ------------- |
| `--account`       | `-a`  | AWS account or profile name                          | Auto-detected |
| `--region`        | `-r`  | AWS region(s), comma-separated                       | All regions   |
| `--limit-regions` |       | Limit scan to specific regions                       | -             |
| `--export-format` | `-f`  | Export format (`csv`, `xlsx`, `json`, `both`, `all`) | `csv`         |
| `--mode`          |       | Scan mode (`basic`, `detailed`, `security`, `cost`)  | `basic`       |
| `--services`      | `-s`  | Comma-separated list of services                     | All services  |
| `--incremental`   |       | Only output new or changed resources                 | `false`       |
| `--min-interval`  |       | Skip scan if recent scan within N minutes            | -             |
| `--skip-global`   |       | Skip global services                                 | `false`       |
| `--only-global`   |       | Scan only global services                            | `false`       |
| `--debug`         |       | Show raw error output                                | `false`       |

## Scan Modes

### basic

Standard inventory scan with essential resource information.

### detailed

Extended scan with additional metadata and relationships.

### security

Security-focused scan emphasizing:

- Security groups and NACLs
- IAM policies and roles
- Encryption settings
- Public accessibility

### cost

Cost-optimization focused scan including:

- Resource utilization metrics
- Reserved instance coverage
- Savings opportunities

## Examples

```bash
# Full cross-region scan (all regions)
cloudops-tools init

# Security-focused scan with Excel export
cloudops-tools init --mode security --export-format xlsx

# Scan only specific services across regions
cloudops-tools init --services Lambda,DynamoDB,SQS

# Limit to specific regions
cloudops-tools init --limit-regions us-east-1,us-west-2,eu-west-1

# Cost analysis mode
cloudops-tools init --mode cost --export-format xlsx

# Skip global services for faster regional scan
cloudops-tools init --skip-global --region us-east-1

# Scan only global services
cloudops-tools init --only-global

# Incremental scan - only output changed resources
cloudops-tools init --incremental
```

## Incremental Scanning

The `--incremental` flag enables smart scanning that only outputs resources that are new or have changed since the last scan:

```bash
# First scan - all resources are output
cloudops-tools init

# Second scan - only changed resources are output
cloudops-tools init --incremental
```

### How It Works

1. Resource fingerprints (hashes of key attributes) are stored in the SQLite database
2. On subsequent scans, new fingerprints are compared with stored ones
3. Only resources with changed fingerprints are written to output files
4. Summary shows: new, changed, unchanged, and removed resource counts

### Benefits

- **Smaller output files**: Focus on what actually changed
- **Faster review**: No need to scan through unchanged resources
- **Change tracking**: See exactly what's different between scans

### Example Output

```
Incremental: 5 new, 3 changed, 142 unchanged
Output file: inventory-output/123456789012/init-incremental-20240215.csv
```

## Scan Deduplication

The `--min-interval` flag prevents duplicate scans by skipping if a recent scan exists:

```bash
# Skip scan if one was done in the last 60 minutes
cloudops-tools init --min-interval 60

# Useful for cron jobs to avoid redundant scans
cloudops-tools init --min-interval 1440  # 24 hours
```

### How It Works

1. Checks the SQLite database for the last scan time
2. If a scan completed within the specified interval, exits immediately
3. Otherwise, proceeds with the scan normally

## Output

The command generates inventory files in the `inventory-output/{account-id}/` directory with the format:

- `inventory-{date}-{time}.csv` (or `.xlsx`, `.json`)

## Historical Storage

All inventory runs are automatically stored in a local SQLite database at `~/.config/cloudops-tools/inventory.db`. This enables:

- **Query past runs**: View scan history without AWS API calls
- **Change detection**: Compare resources between runs
- **Incremental scans**: Only output changed resources
- **Scan deduplication**: Skip redundant scans

### What's Stored

| Table                   | Purpose                                                  |
| ----------------------- | -------------------------------------------------------- |
| `inventory_runs`        | Scan metadata (account, mode, timestamp, resource count) |
| `resources`             | Full resource details for each run                       |
| `resource_fingerprints` | Hashes for incremental change detection                  |
| `describe_cache`        | Cached describe results with TTL                         |

### Querying Historical Data

Use the [`query`](/docs/cli/commands/query) command to analyze historical data:

```bash
# List all runs for an account
cloudops-tools query --runs --account 123456789012

# Detect changes since last run
cloudops-tools query --changes --account 123456789012

# Query specific resource types
cloudops-tools query --type EC2 --days 7 --account 123456789012
```

**Note:** Always specify `--account` with the same account ID used during `init` to query your data.
